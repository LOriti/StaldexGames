# Cubicle

A single-player office survival game wrapped as a native mobile app via Capacitor. The app ships as **Cubicle** (a pun on the office cubicle and the toilet cubicle); in-game it presents as a fake corporate wellness dashboard called **Vitals 365** — the joke is the player installs Cubicle and is then trapped inside its earnest wellness-app wrapper.

The game itself is a self-contained HTML file in `www/index.html` — no build step required for the game code.

---

## What this is

- **`www/index.html`** — the entire game. One HTML file with inline CSS and JS. No bundler, no transpile, no external assets except system fonts.
- **Capacitor** — wraps the HTML in a native Android WebView so it can be installed as an app.
- **Cubicle** is the app name (on Play Store and on the phone home screen). **Vitals 365** is the in-game wellness-app wrapper brand — it appears on the in-game logo and page title.

**Bundle ID:** `com.tldkgames.cubicle`
**Display name on phone:** `Cubicle`
**Primary target:** Android. iOS files are configured but will be built by someone else.

## Quickstart (Android)

```bash
npm install
npx cap add android
npx cap sync
npx cap open android
```

In Android Studio: wait for Gradle sync (first time takes a while), then hit Run. Pick an emulator or a connected device with USB debugging enabled.

If you just want to test the game in a browser without any of the native shell:
```bash
xdg-open www/index.html   # Linux
open www/index.html        # macOS
start www/index.html       # Windows
```

## Editing the game

Edit `www/index.html` directly. After any edit:

```bash
npx cap sync
```

Then reload in Android Studio (or re-run). There is no transpile step; the HTML you write is what the WebView runs.

### Architecture inside index.html

The file has three logical sections:

1. **CSS** (lines ~1–600) — visual styling. Uses CSS variables prefixed `--viva-` (historical name from the earlier "Viva Insights" version of the wrapper before it became Vitals 365). Variables work fine, no need to rename.
2. **HTML body** (~600–700) — header, tiles, activity feed, wellbeing meters, action grid, modals.
3. **JavaScript** (~700–end) — game state, action handlers, event system, callbacks, day/week lifecycle.

The JS is procedural and heavily commented. Major systems are flagged with `// ==================== SECTION ====================` banners.

See `HANDOFF.md` for the full mechanics/design reference.

## Icon

`resources/icon.svg` is the source. The design is a top-down cubicle (three walls + doorway, ambiguously office-or-toilet) with a stick figure inside, on Teams-purple background. There's a subtle "V" in the corner referencing Vitals 365.

To generate all required Android icon sizes:

```bash
npm run assets
```

This uses `@capacitor/assets`. It expects `resources/icon.svg` (or `icon.png` at 1024×1024) and writes out all the launcher icon variants and splash screens with the configured background colour (`#33344a`, the Teams deep purple).

If you want to swap to a hand-drawn 1024×1024 PNG, just replace `resources/icon.svg` with `resources/icon.png` and re-run `npm run assets`.

## Building for Play Store

1. Open Android Studio: `npx cap open android`
2. `Build → Generate Signed Bundle / APK` → choose **Android App Bundle (.aab)**
3. Create or select a keystore (back this up — losing it means you can never update the app)
4. Build release variant
5. Upload the `.aab` to Google Play Console

**Important:** This game contains references to prescription stimulants (dexamphetamine), pre-workout, nicotine, and bowel-related humour. Rate it **Mature 17+** on Google Play. Trying to slip through as a lower rating will get the listing rejected.

Suggested store metadata:

- **Title:** Vitals 365: Office Survival
- **Short description:** A single-player office survival game disguised as a wellness dashboard.
- **Long description:** Make it to Friday without crashing. Manage focus, bowel pressure, jitter, and stim load across five days of corporate purgatory. Take coffee, nicotine, energy drinks, pre-workout, or — if you're brave — a dexi. Avoid Linda chewing apples, Gary from IT, Brad's "quick chats," and Greg's Strava recaps. Lock in once a day if the stars align. Don't shit yourself in the open-plan office.

## Common Claude Code prompts

After this initial setup, things you might ask Claude Code to do:

- **"Add a new event"** — point it at the `EVENTS` array in `www/index.html` and the existing event format
- **"Tweak the lock-in odds"** — point it at the `commitLockIn` function
- **"Add a new action to the action grid"** — needs an HTML button + handler in the `doAction` function + (optional) CSS class
- **"Add a sound effect"** — drop a sound file in `www/sounds/` and use `new Audio('sounds/...').play()`
- **"Add save state via localStorage"** — note that `localStorage` works in the Capacitor WebView (unlike in Claude.ai artifacts where storage is sandboxed)

Refer Claude Code to `HANDOFF.md` for game design context before making changes to mechanics.
